1 · Sesión institucional

Utiliza la sesión activa de este mismo navegador. Si no hay sesión, ingresa aquí. Las credenciales se envían exclusivamente a Supabase Auth, no se guardan en el reporte.

2 · Batería automática

Verifica identidad, ámbito territorial, funciones protegidas y aislamiento de tablas. No edita, crea ni elimina expedientes. Cuando una prueba no tiene datos de referencia suficientes, marca NO EVALUABLE, no PASS.

Un PASS aquí valida el comportamiento de las solicitudes probadas con la sesión real. No certifica todas las políticas internas, MFA, revocación del JWT ni operaciones que modifican datos. La sesión debe permanecer activa durante la batería.

3 · Alcance de la validación

El comprobador se publica como código cliente. La protección efectiva sigue residiendo en Supabase Auth, las políticas SQL y la autorización interna de cada RPC. No almacena ni exporta identificadores de usuario, folios, correos, tokens, respuestas clínicas ni contraseñas. Los resultados solo contienen estados y conteos agregados. Las pruebas de escritura y de revocación real deben ejecutarse en un entorno de staging con identidades y datos sintéticos.
